# AI provider profile (F4)

A provider (company) generates a short public presentation with AI from its
technical sheet, reviews and edits it, and approves it. Nothing generated by
the AI is visible to customers until the provider approves it.

## Flow

1. The provider saves its technical sheet (#22).
2. In **AI profile** it taps **Generate profile with AI**. The app calls the
   `generate-profile` Edge Function.
3. The function saves the result as a **draft** in `provider_profiles`.
4. The provider edits the headline and description and taps **Save changes**.
   The profile stays a draft. It can also **Generate again**.
5. **Approve and publish** asks for confirmation, saves the current edits and
   sets `status = 'approved'`. A trigger sets `approved_at`.
6. Customers only see approved profiles (RLS).

Editing or regenerating an approved profile is planned for Sprint 2.

## Edge Function `generate-profile`

- `POST`, no body. It uses the caller's session (JWT) and never the service
  role key, so every query also goes through RLS.
- Reads the newest technical sheet of the caller and the city of its address.
- Sends only the sheet data to the LLM (no contact data). The prompt is in
  `supabase/functions/_shared/prompts.ts` (`PROMPT_VERSION`).
- Validates the JSON answer (`_shared/profile.ts`) and retries once if it is
  invalid.
- Saves the draft with an upsert (one profile per provider).

| Code | HTTP | Meaning |
|---|---|---|
| `unauthorized` | 401 | No valid session |
| `forbidden` | 403 | The user is not a company |
| `no_technical_sheet` | 409 | The provider has no technical sheet |
| `already_approved` | 409 | The profile is already published |
| `too_many_requests` | 429 | Generated less than 30 s ago |
| `llm_timeout` | 504 | The LLM took more than 20 s |
| `llm_unavailable` | 502 | The LLM returned an error |
| `invalid_ai_output` | 502 | The answer was invalid twice |
| `llm_not_configured` | 500 | Missing LLM secrets |
| `internal_error` | 500 | Unexpected error |

### Configuration

The LLM is any OpenAI-compatible API (see
[ADR 002](../decisions/002-llm-provider.md)). Secrets:

- `LLM_BASE_URL`
- `LLM_API_KEY`
- `LLM_MODEL`

Locally they go in `supabase/functions/.env` (git-ignored). In the cloud:
`supabase secrets set ...`. Never put them in the mobile app.

## Mobile app

Code in `mobile/src/features/ai-profile/`, screen in
`mobile/src/app/(provider)/ai-profile.tsx`.

- `api/`: Supabase calls and the mapping of function error codes to messages.
- `hooks/`: TanStack Query hooks (`profileKeys.ts`) and the form hook.
- `components/AiProfile.tsx`: chooses what to show: loading, error, no sheet,
  no profile, draft editor or published profile.

## How to test locally

```
npx supabase start
npx supabase functions serve --env-file supabase/functions/.env
cd mobile && npx expo start
```

1. Log in as a company with a technical sheet and open **AI profile**.
2. Generate, edit the headline, save, approve and check **Published**.
3. In Studio, the `provider_profiles` row has `status = approved` and
   `approved_at` set.
4. RLS: run `supabase/test/provider_profiles_rls.sql` in the SQL Editor.

Automated tests: `deno test` in `supabase/functions` and
`npm test -- ai-profile` in `mobile`.
